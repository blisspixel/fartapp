# Language, localization, and universal translation

F.A.R.T. Lab is not an English simulation translated after the fact. When
present, law-defined quantities, identities, actions, observations, and proof
claims use stable semantic identifiers. None of those concepts is mandatory.
A communication profile may use symbolic language, sound, image, pressure,
chemistry, electromagnetism, collective state, a declared fictional channel, or
no Lab-accessible mapping. Human language is one optional profile, not the
reference class.

This is a design contract. Text in the current Go oracle is an English-only
presentation. Its stable IDs and JSON fields are locale-invariant engineering
tokens, which does not make them language-neutral or universally meaningful.

“Universal Flatulence Translator” is the comic product name, not a claim that
one universal language, meaning graph, humor response, or translation procedure
exists. Scientifically, the instrument performs loss-aware mappings among
declared signals, structures, relations, candidate meanings, and presentation
profiles. It may retain several incompatible hypotheses, produce a structural
mapping without semantic translation, or refuse the mapping precisely.

## A locale-invariant reference

The canonical Reference Pfft key is `ref:rp1:v1`. It does not select a country,
language, locale, species, anatomy, room function, or cultural norm. Its first
Earth realization declares `101 325 Pa`, `293.15 K`, `50 %` relative humidity,
standard gravity, a project reference enclosure, a reference observer, and a
synthetic uncertain low-energy source. The fixture is not a body. The enclosure
is a reproducible geometry, not a claim that buildings, bathrooms, or tiled
rooms are universal.

`Reference Pfft` and `RP-1` are English working titles. Interfaces display a
reviewed localized title and description while retaining the stable key in
inspectable metadata. A default everyday encounter may occur in any compatible
ordinary context. A bathroom is one optional Earth scenario.

`F.A.R.T. Lab` is the brand mark and its English expansion is not a translation
test. Every shipping locale provides a reviewed spoken name, pronunciation,
descriptor, acronym-expansion policy, and discovery aliases. A locale may keep
the mark, explain it, or use a locally effective descriptor without forcing the
English initials into an awkward joke.

Canonical identifiers are locale-invariant ASCII engineering tokens. Many use
English-derived mnemonics for developer ergonomics, but they are not user-facing
natural language and never select physical or cultural behavior. Localized
schema introspection supplies reviewed labels, descriptions, examples, units,
and aliases while canonical automation grammar remains stable.

Model definitions follow the same rule. A stable model ID, revision, provider,
implementation, learned-artifact digest, and evidence do not change by locale.
Forecast-desk names such as `Pfft Reference`, `Breeze`, or `Shortcut` are
localized presentation keys, not lookup authority. A translated nickname
cannot select a model, alter ensemble membership, hide a `SURROGATE` label, or
change comparison results. Machine reports may include requested localized
labels beside stable IDs, never instead of them.

## Human-language contract

Every translatable message has:

- Stable semantic key and source locale.
- Typed variables with quantity, unit, grammatical role, and escaping policy.
- Selectors for plural, grammatical features, register, and audience where
  supported.
- Plain, terminal, speech, caption, and compact variants when meaning differs.
- Translator note, screenshot or state context, and maximum-width guidance.
- Review state, bundle version, and named locale steward competent in the exact
  language, script, region, register, and feature context.

Messages are complete units. Code never concatenates translated fragments into
English word order. Numbers, dates, lists, units, quotation marks, names, and
plural categories follow versioned Unicode CLDR data. Earth continuum
scientific storage uses SI. Other law contexts use their declared canonical
representation, or no unit system where units are inapplicable. Display
formatting cannot change a parsed value or scenario digest.

The project evaluates Fluent and Unicode MessageFormat against the dependency
budget before freezing a message format. The chosen implementation must work
offline in Rust, support rich grammatical selection, reject unsafe markup, and
produce deterministic output from pinned locale data.

## CLI behavior

The executable name and canonical script grammar remain stable for portable
automation. Interactive help, prompts, explanations, errors, examples, and
search accept a selected locale. Reviewed localized command aliases may lower to
canonical commands in an interactive terminal, but generated scripts and
machine receipts always show the canonical form too.

```console
fart --locale fr help case run
fart ask --language ja request.txt --dry-run
fart case inspect run.fart --locale ar
fart config set interface.locale system
```

Locale precedence is explicit: command flag, project configuration, user
configuration, supported operating-system locale, then the release fallback.
Machine JSON and JSONL use stable semantic keys, typed values and relations, and
unit codes only where units exist. Localized text is optional and separately
labeled. Error codes and exit status never change by locale.

Unknown or incomplete locale data falls back per message and reports the
fallback in verbose diagnostics. It never prints a half-localized sentence by
combining fragments from two languages.

## Natural-language generation

`fart ask` identifies or accepts the request language, then compiles text into a
typed proposal. Detection is never silently trusted for a short or ambiguous
request. The interpretation receipt records source language, spans, applicable
normalized fields, assumptions, uncertainty, unsupported concepts, fallbacks,
and the version of the language grammar or optional model adapter. Quantities
appear only where the law contexts define them.

Each language receives its own examples, ambiguity corpus, units, idioms,
registers, and human evaluation. A translation into English is not accepted as
the only semantic evidence. Optional language models propose typed fields but do
not control physics and cannot substitute for a maintained offline exact path.

Agent JSONL, MCP, and A2A surfaces operate on locale-invariant actions and
observations. Agents may request localized natural language as a read-only view
profile. A benchmark records the language and does not compare exact typed input
with natural-language input as if they were the same task.

## Locale humor packs and sound symbolism

When compatible retained claims, a human locale, and an interpretation path
exist, a versioned `HumorCue` may offer an optional interpretation. It reads
only the retained account and presentation history. It cannot alter a law
context, case input, operation, solver, numerical result, classification,
evidence, admission, safety decision, score, progression, or identity. Its
successful output is localized wording, a caption, an accessible alternative,
a presentation-order suggestion, or `no_joke`. `no_joke` is a complete result,
not a missing translation or a judgment about the audience.

A `LocaleHumorPack` contains:

- A stable cue key, required retained claims, intended comic mechanism, and
  declared joke target.
- A source-locale intent note and complete localized realizations, not a bag of
  fragments to assemble across languages.
- Register and content tags selected independently from locale.
- Text, speech, caption, compact-terminal, and accessibility alternatives where
  those channels apply.
- Review scope, reviewer roles, revision, known gaps, and a `no_joke` path.

The pack transcreates intent rather than requiring literal translation.
Understatement, legal phrasing, rhythm, wordplay, and a deliberately clinical
non-joke may all be correct outcomes. A localized onomatopoeia such as the
working English `pfft` is presentation metadata, not a physical class or
waveform lookup. Languages differ in sound-symbolic conventions, and observed
sound-meaning associations are tendencies rather than a universal dictionary
([Blasi et al., 2016](https://doi.org/10.1073/pnas.1605782113)). Game-humor
localization likewise benefits from preserving comic function instead of word
shape ([Lee, 2013](https://doi.org/10.15749/jts.2013.14.1.006)).

Language, region, script, register, content level, age or maturity context,
religious or cultural context, direct-language tolerance, and accessibility are
separate profile axes. Selecting one never infers the others. There is no
French, Japanese, American, Martian, or species-essential fart preset. Locale
never selects pressure, composition, wetness, cleanliness, body, diet,
intelligence, morality, social meaning, or morphology.

A declared morphology may be described where the case needs it. It never
selects accent, locale, culture, religion, personality, intelligence, morality,
music, clothing, food, or comic rank. Morphology-aware humor targets a Lab
adapter, category error, or institutional assumption, never a body, species, or
community. A locale pack may decline the cue with `no_joke`.

Humor is reviewed in running product context and may be rewritten, narrowed, or
omitted. Material involving a living culture, religion, taboo, identity, or
high-affinity analogue requires the safeguards in [CULTURE.md](CULTURE.md),
including competent situated review and a correction or withdrawal path.
Machine translation can propose a draft but cannot approve it.

## Writing systems and terminal safety

The product supports Unicode logical text, extended grapheme clusters,
right-to-left and mixed-direction text, East Asian width, combining marks,
vertical-script alternatives where a surface can support them, and safe font
fallback. Security-sensitive identifiers, quantities, hashes, commands, and
paths are isolated from surrounding bidirectional text.

Tests cover:

- Unicode normalization and confusable-sensitive boundaries.
- Grapheme cursor movement, deletion, truncation, wrapping, and cell width.
- Right-to-left layout and mixed-direction quantities, hashes, and commands.
- Plural, agreement, register, and unit formatting fixtures.
- Long expansion, narrow terminals, missing glyphs, and fallback fonts.
- Control characters, terminal escapes, bidi controls, hostile translations,
  and untrusted names.
- Screen readers, captions, speech ordering, copy and paste, search, and logs.
- Same canonical action, case result, certificate, score, and any applicable
  event claim across every locale.

Plain-text fallbacks preserve supported meaning. ASCII mode identifies its
transliteration scheme or fallback locale, preserves canonical machine values,
and never claims full locale parity when original-script text is unavailable.
Transliteration is optional and never replaces the original script by default.

## Nonhuman and cross-world translation

A `LanguageProfile` is only one kind of communication profile. A communication
context declares only the properties it supports. Candidate capabilities
include:

- Available channels and optional bandwidth, latency, direction, and noise.
- Symbol inventory or continuous signal space.
- Segmentation, ordering or temporal structure, compositional rules, and ambiguity.
- Embodiment, privacy, taboo, access, and institutional control when those
  concepts exist.
- What can be sensed directly, inferred, rendered, or not represented.

The Universal Flatulence Translator constructs a provenance-bearing
interpretation representation only when the law contexts and bounded case scope
support one. Other profiles may expose continuous relations, opaque states, interaction protocols,
or structural invariants without propositional decomposition. No meaning graph,
symbol inventory, segmentation, or compositional grammar is presumed universal.

It keeps four operations distinct: semantic translation with a declared shared
semantic basis; structural mapping of selected relations or invariants; signal
transcoding under channel constraints; and experience analogy as explicitly
comic or artistic presentation. A successful structural mapping is never
labeled semantic translation. Loss, ambiguity, approximation, taboo, privacy,
refusal, prohibition, undecidability, and lack of compatibility retain distinct
locale-invariant result codes.

An interpretation record is staged. It keeps law-supported observations or
claims, physical or formal classification, structural mapping, semantic
hypotheses, localized gloss, and optional comic overlay separate. No later stage
can rewrite an earlier claim.

Translation loss is a typed vector rather than one confidence percentage. Its
applicable axes include channel, segmentation, structure, ontology, situated
context, ordering, and locale. An axis may be absent, inapplicable, unknown,
ambiguous, private, refused, prohibited, or undecidable. Dissent, abstention,
and multiple candidate mappings remain visible instead of being averaged into a
false consensus. The fictional [intercontextual council prototype](CONSORTIUM.md)
demonstrates the intended player-facing humor and record structure.

Fictional language and signal generation starts with authored grammars and
bounded combinators. It does not create pseudo-language by altering spelling or
borrowing a living script as alien decoration.

## Translation workflow

1. Freeze semantic keys and screenshots for one feature slice.
2. Provide translator notes, variables, states, length constraints, and audio
   context.
3. Translate in context with a named locale steward competent in the exact
   language, script, region, register, and feature context.
4. Run schema, placeholder, Unicode, layout, accessibility, and safety checks.
5. Review the feature in CLI, TUI, captions or speech, and native context where
   applicable.
6. Conduct humor, scientific, and cultural review by people competent in that
   locale.
7. Publish bundle coverage, known gaps, fallback behavior, and review revision.

Machine translation may create an internal draft. It cannot mark a bundle
reviewed, approve a joke, or become the only reviewer for warnings, consent,
safety, metrology, accessibility, or cultural material.

## Release gates

- The launch locale set is chosen by sustained reviewer ownership and complete
  product coverage, not by an arbitrary market list.
- Before 1.0, the script-capability matrix must exercise left-to-right,
  right-to-left, and representative Han, kana, and Hangul layout behavior, in
  addition to pseudo-locales for expansion, mirrored layout, accents, missing
  messages, and hostile inputs. Shipping coverage is reported as named BCP 47
  locale profiles with language, script, and region where applicable, never as
  one `CJK` locale checkbox.
- Each shipping locale has its own golden path, search and discovery aliases,
  input, typography, humor, lyrics, and sensitivity evidence with sustained
  competent reviewer ownership.
- Core play, science, errors, help, update, safety, accessibility, radio, and
  archive workflows cannot ship as a mixture of reviewed and accidental English.
- A locale may ship as preview only with visible coverage, fallback, and review
  status. Preview status cannot apply to safety-critical instructions.
- Every localized screenshot and media asset follows the same provenance and
  rights manifest as other documentation media.
- Localization updates cannot alter canonical scenarios, record nonces, random
  streams, physics, proof, score, progression, or archive identity.
- Switching locale, register, content level, caption style, accessibility
  alternative, or `no_joke` preserves the same retained account, scientific
  values, claim paths, operation disposition, and applicable result identity.
- Every shipping humor cue names its required retained claims and joke target.
  A cue with unmet predicates is unavailable rather than approximately true.
- Locale, morphology, content level, maturity context, cultural context, and
  accessibility vary independently in regression fixtures. No profile is used
  as a proxy for another.
- Child-accessible paths avoid humiliation, sexualization, body shame, graphic
  deposition, contamination panic, and coercion. They remain complete with
  comedy disabled and do not imply an age rating or child-suitability claim.
- A joke cannot require sound, color, animation, haptics, fast timing, or speech
  as its only understandable channel. Applicable alternatives receive review in
  context, not only placeholder and layout checks.

The cultural safeguards in [CULTURE.md](CULTURE.md) and interface rules in
[INTERFACES.md](INTERFACES.md) are part of this contract.
